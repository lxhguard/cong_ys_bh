# 深拷贝

## 手撕实现

```js
function deepClone(target, map = new WeakMap()) {
  // ① 基本类型 / null / 函数：直接返回
  //    函数不深拷贝：函数没有可复制的内部状态，约定为浅引用
  if (target === null || typeof target !== 'object') return target;

  // ② 循环引用：命中缓存直接返回，避免死递归
  if (map.has(target)) return map.get(target);

  // ③ 特殊内置对象
  if (target instanceof Date) return new Date(target.getTime());
  if (target instanceof RegExp) {
    const clone = new RegExp(target.source, target.flags);
    clone.lastIndex = target.lastIndex;   // 保留 lastIndex
    return clone;
  }
  if (target instanceof Map) {
    const clone = new Map();
    map.set(target, clone);               // 先占位，key 也可能有循环引用
    target.forEach((value, key) => clone.set(deepClone(key, map), deepClone(value, map)));
    return clone;
  }
  if (target instanceof Set) {
    const clone = new Set();
    map.set(target, clone);
    target.forEach((value) => clone.add(deepClone(value, map)));
    return clone;
  }

  // ④ 数组 / 普通对象：先创建占位对象注册进 map，再递归拷贝属性
  const result = Array.isArray(target) ? [] : {};
  map.set(target, result);

  // Reflect.ownKeys 覆盖：字符串 key + Symbol key + 不可枚举 key
  Reflect.ownKeys(target).forEach((key) => {
    if (key === 'length' && Array.isArray(target)) return; // 数组 length 自动推导
    result[key] = deepClone(target[key], map);
  });

  return result;
}
```

## 边界清单（面试时主动讲，边写边说）

| 边界 | 处理方式 | 为什么 |
|---|---|---|
| 循环引用 | `WeakMap` 缓存 | 没有缓存会死递归爆栈 |
| **为什么用 WeakMap 不用 Map** | 弱引用 | 源对象被回收后，缓存记录不阻碍 GC，防内存泄漏——这是加分点 |
| Symbol / 不可枚举属性 | `Reflect.ownKeys` | `Object.keys`/`for...in` 拿不到 Symbol key；ownKeys 全覆盖 |
| Date / RegExp | 构造新实例 | `RegExp` 还要带 `lastIndex` |
| Map / Set | 先占位再递归 | Map 的 **key** 也可能是对象且可能循环引用 |
| 数组 | 独立分支 + 跳过 length | `length` 由元素数量自动推导，手动拷贝反而可能写错 |

## 缺陷话术（P6 评分关键：写完主动说）

> 这个版本还有三个已知边界，我说明一下：
> ① **函数和类实例**：函数浅引用；class 实例克隆后会变成普通对象、`instanceof` 失效、原型链丢失——如果需要保留原型，可以额外判断 `Object.getPrototypeOf` 再重建；
> ② **访问器属性**：getter 会被执行并降级成普通数据属性，setter 丢失；
> ③ **属性描述符**：`Reflect.ownKeys` 拷了值和 Symbol，但 writable/enumerable/configurable 没保留。

## 对比表（面试官爱问"那为什么不用现成的"）

| 方案 | 循环引用 | 函数 | Symbol | Date | Map/Set | 原型 |
|---|---|---|---|---|---|---|
| `JSON.parse(JSON.stringify())` | ❌ 报错 | ❌ 丢失 | ❌ 丢失 | ❌ 变字符串 | ❌ 变 `{}` | ❌ |
| `structuredClone`（原生） | ✅ | ❌ 抛错 | ❌ 丢失 | ✅ | ✅ | ❌ |
| 手写版 | ✅ | 浅引用 | ✅ | ✅ | ✅ | ❌（可扩展） |

> 所以手写版的核心价值不是"最强"，而是**按需取舍**：真实场景优先 `structuredClone`，需要保 Symbol/函数时才手写。

## 面试讲稿（约 2 分钟，按这个节奏）

> 动笔前先确认：「要处理循环引用、Symbol、Date/Map/Set 吗？一般我默认都要。」——**这句本身就是 P6 信号**。
>
> 然后边写边讲：基本类型直接返回；用 `WeakMap` 做循环引用缓存，选 WeakMap 是因为弱引用、不阻碍 GC；Date/RegExp/Map/Set 走特判，Map/Set 先占位再递归（因为 key 也可能循环引用）；数组和对象用 `Reflect.ownKeys` 递归，这样 Symbol key 和不可枚举属性也能覆盖；复杂度 O(n)。
